# 本地 AI 音乐（编曲优先）设计规格

> 日期：2026-07-10  
> 状态：待用户确认  
> 参考产品：[ai6666 生成页](https://ai6666.com/music/) · [教父编曲房](https://ai6666.com/music/studio/)

## 1. 目标

在本地复刻「教父音乐 / Suno」类产品的**编曲与出歌核心体验**：

1. **编曲房**：要求 / 歌词 → LLM（DeepSeek）→ 结构化歌词（段落标签）+ 风格标签  
2. **专业创作页**：结构标签、流派 / 情绪 / 乐器 / 人声 / 速度 → 本地开源模型 → 音频  
3. **歌词**：优先接 DeepSeek（用户已确认可行）；不自研歌词模型  

**非目标（第一期不做）**

- 账号体系、付费次数、广场社区、微信登录  
- 一比一抄袭商业模型权重或逆向 API  
- 云端 Suno / 教父 API 依赖（可留扩展口，默认关闭）  
- 完整 DAW（多轨混音、MIDI 精细编辑）

## 2. 方案对比与选型

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 仅编曲房 | DeepSeek 产出结构化歌词+风格，不出音频 | 最快落地 | 没有「出歌」，体验不完整 |
| **B. 编曲房 + 本地开源出歌（选定）** | DeepSeek 编排 + ACE-Step 等本地生成 | 真正本地可控；无按次费用；可迭代 | 需 GPU；音质仍低于顶尖闭源 |
| C. 编曲房 + 云端 API | UI 本地，音频走第三方 | 音质可能更好 | 依赖外部额度；非「本地」 |

**音乐骨干模型推荐：ACE-Step 1.5（MIT）**

- 支持歌词 + 人声 + 伴奏的完整歌曲生成  
- 消费级显卡可跑（官方称约 &lt;4GB VRAM；3090 约 10s 级整曲量级，视配置而定）  
- LM planner + DiT：与「先编排、再渲染」产品流程契合  
- 备选：DiffRhythm 2（更快偏节奏）、LeVo 2（歌词对齐/情绪强）、YuE（早期全曲方案，更重）

## 3. 产品范围（MVP）

### 3.1 页面

| 页面 | 对应参考 | MVP 能力 |
|------|----------|----------|
| 编曲房 `/studio` | 教父编曲房 | 要求框、可选歌词、语言、开始编排、结果预览、一键带去创作 |
| 创作页 `/create` | 专业模式 | 歌曲要求、歌词+结构标签、风格维度、标题、纯音乐、生成、播放/下载 |
| 我的 `/library` | `/music/my/` | 本地任务列表、状态、播放、下载（无登录） |
| 描述模式 | 可选二期 | 自然语言一键出歌（可先用 ACE-Step 自带 planner） |

### 3.2 编曲输出约定

DeepSeek 编排结果统一为 JSON，例如：

```json
{
  "title": "可选标题",
  "language": "zh",
  "lyrics": "[前奏]\\n...\\n[主歌]\\n...\\n[副歌]\\n...",
  "style": {
    "genres": ["流行", "国风"],
    "moods": ["治愈"],
    "instruments": ["钢琴", "弦乐"],
    "vocals": ["女声"],
    "tempo": "中速"
  },
  "style_prompt": "Chinese pop, guofeng, healing, female vocal, piano, strings, mid tempo"
}
```

结构标签与参考站对齐：`前奏 / 主歌 / 预副歌 / 副歌 / 桥段 / 尾奏 / 间奏`（内部可映射为模型所需的 `[Intro]` 等英文标签）。

## 4. 系统架构

```
┌─────────────────────────────────────────────────────────┐
│  Web UI (Next.js)                                        │
│  编曲房 / 专业创作 / 本地曲库                              │
└───────────────┬───────────────────────────┬─────────────┘
                │ HTTP/JSON                 │ 轮询任务状态
                ▼                           ▼
┌──────────────────────────┐    ┌──────────────────────────┐
│  API Gateway (FastAPI)   │    │  静态/音频文件服务         │
│  /arrange  /generate     │    │  outputs/*.wav            │
│  /jobs/:id  /library     │    └──────────────────────────┘
└──────────┬───────────────┘
           │
     ┌─────┴──────┐
     ▼            ▼
┌─────────┐  ┌────────────────────┐
│ DeepSeek│  │ Worker + GPU       │
│ 编排/歌词│  │ ACE-Step 1.5 推理  │
│ (云端API)│  │ 队列：单卡串行优先  │
└─────────┘  └────────────────────┘
```

**原则**

- UI 与推理解耦：生成任务异步入队，避免 HTTP 超时  
- 编排（LLM）与出歌（扩散/DiT）分服务，可单独扩缩  
- 所有音频与元数据落本地磁盘 + SQLite（或 JSON 索引）

## 5. 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | Next.js + TypeScript | 复刻参考站信息架构；视觉可自有品牌，不抄商标 |
| 后端 | FastAPI + Python 3.11+ | 与 AI 生态一致 |
| 队列 | 内存队列 / RQ / 简单 asyncio 队列 | MVP 单机单卡即可 |
| 编排 LLM | DeepSeek API | 可配置 `DEEPSEEK_API_KEY`；预留本地 LLM 接口 |
| 音乐模型 | ACE-Step 1.5 | 权重下载到 `models/`（gitignore） |
| 存储 | SQLite + `outputs/` | 任务、歌词、风格、文件路径 |
| 部署 | 本机 Windows + NVIDIA CUDA | 第一目标环境 |

## 6. 数据流

### 6.1 编排

1. 用户提交 `requirement` + 可选 `lyrics` + `language`  
2. API 组装 system/user prompt（强调结构标签与风格维度）  
3. DeepSeek 返回 JSON → 校验 → 返回前端  
4. 「一键带去创作」把结果写入创作页表单（query 或临时 draft id）

### 6.2 出歌

1. 创作页提交 `lyrics` + `style_prompt` + `title` + `instrumental` 等  
2. 创建 Job（`queued`）→ Worker 拉取 → `running`  
3. 调用 ACE-Step：歌词 + caption/style → wav/mp3  
4. 写回 `succeeded` / `failed`，前端轮询后播放下载  

## 7. UI 设计要点（参考但不照搬品牌）

- 顶栏：生成音乐 / 编曲房 / 我的  
- 主卡片：白底圆角、主 CTA 用暖色渐变（粉→橙）  
- 专业模式：结构标签快捷插入；风格：最优推荐 + 流派/情绪/乐器/人声/速度  
- 本地版去掉：登录注册、领次数、广场、认证徽章等商业元素  

## 8. 硬件与性能假设

| 配置 | 预期 |
|------|------|
| ≥8GB 显存（理想 12GB+） | 可跑 ACE-Step 1.5 常规档 |
| 24GB（3090/4090） | 更稳、可尝试 XL 或更高质量参数 |
| 仅 CPU | 不作为 MVP 目标（过慢） |

计划书实施前需确认本机 GPU 型号与显存；若显存不足，降级为更小 checkpoint 或缩短时长。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 开源音质仍不如 Suno 顶尖 | 产品定位「本地可控 MVP」；支持调参/多种子重试 |
| 中文说唱等风格偏弱（ACE-Step 已知局限） | 风格库避开弱项；后续可加 LoRA |
| 显存不足 | 量化、短时长、关 XL |
| DeepSeek 编排格式漂移 | JSON schema 校验 + 重试 + 本地兜底模板 |
| 模型许可证/商用 | 优先 MIT/Apache；权重与依赖在 README 标明 |

## 10. 成功标准（MVP）

1. 编曲房：输入要求，30 秒内得到合法结构化歌词 + 风格 JSON  
2. 创作页：提交后能排队、生成、播放、下载至少一首完整曲（含人声或纯音乐）  
3. 曲库：刷新后仍能看到历史任务  
4. 无外部音乐 API 依赖即可完成上述闭环  

## 11. 分期

| 期 | 内容 |
|----|------|
| **P0** | 项目骨架、ACE-Step 本地推理通、最小 API「歌词+风格→音频」 |
| **P1** | DeepSeek 编曲房 + 专业创作 UI（参考站信息架构） |
| **P2** | 曲库、任务队列稳健化、风格标签库、最优风格推荐 |
| **P3** | 描述模式、分轨/人声增强、LoRA 个性化、可选云端模型适配器 |
