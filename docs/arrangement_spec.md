# 编曲与节奏设计规范

> 建立于 2026-10-16。这份文档是"我们的歌**应该长什么样**"的长期标尺，以及"怎么把它做出来"的技术路线。
> 它不记录流水（那是 `progress.md`），只记录**判定标准、实测数据、可复用的方法与结论**。
> 每次改动画/节奏相关的代码，先读这里，改完更新这里的数字。

---

## 0. 这份文档要解决什么

用户 2026-10-16 对已交付的英文史诗战斗曲（`outputs/2026-10-15_epic_en`，9 首）的两条意见：

1. **节奏与音高"一条直线"**：全曲同一个节奏，"音调变化也不大"。参照米哈游 Wildfire——
   前期和高潮**不只是音调不同，歌手吐词的密度也不同**：前期明显缓慢，高潮更加集中。
   提出做法：**先模仿顶级音乐的节奏与高低 → 学习其设计 → 再替换/创造我们自己的乐器与歌词**。
2. **高音处有机械杂音**：集中在部分高潮段，**不像人类歌手的破音，是一种"带缺陷的机械音"**。
   并非每首歌都有。

本规范把这两条从"感觉"变成"可测、可改、可回归"的工程项。

## 1. 问题一：节奏与吐词密度

### 1.1 判定标准（用户给的）

- 主歌：慢、疏、留白，字与字之间有时间；音区偏低。
- 副歌：密、集中，吐词快；音区明显更高。
- 整首歌：**不是全程同一个律动**，段落之间要有可听出的密度差与音区差。
- "快慢吐词很重要"——**吐词速率是一个被设计出来的参数**，不是副产品。

### 1.2 实测证据：问题属实，而且方向是反的

新增 `tools/generation/plan_metrics.py`（见 §4），直接读 YuE2 的符号计划（ABC），
统计每个段落人声声部的**音符起音数/秒（≈吐词密度）**、**音区中心与跨度**、静音占比、跳进率。

对 `outputs/2026-10-15_epic_en` 的 23 个候选计划实测：

| 指标 | 实测 | 应有（参考曲待标定） |
|---|---|---|
| 副歌/主歌 吐词密度比 | **1.14**（23 首里只有 15 首副歌更密） | 流行/战斗曲副歌通常为主歌的 1.5–2.5 倍 |
| 副歌−主歌 音区中心 | **+2.7 半音** | 副歌应显著更高（且末副歌常有升调） |
| 主歌密度绝对值 | 1.37 起音/秒（=1.27 词/秒，实测） | — |
| 副歌/主歌 静音占比 | 15% / **23%**（主歌确实更留白 —— 这是**已经对的部分**） | 保持 |
| 单首候选间波动 | 同一首的 c1/c2 比值 0.72–1.60 | 说明**模型自身不稳定**，靠提示词无法保证 |

单曲明细（节选，`logs/plan_metrics_1015.json` 为全量）：

```
plan                                verse  chorus   c/v  v_centre c_centre
01_hammer_and_hymn                   1.55    1.40  0.90     77.2     79.6
04_iron_rain                         1.66    1.19  0.72     75.5     78.6
07_signal_fire                       1.57    1.26  0.81     78.0     80.3
09_small_and_unbroken                1.48    1.55  1.05     76.3     78.6
```

**结论：这不是"没写好"，而是模型默认就这么写。** 它把每个段落都填成差不多密度的音符，
不少曲目副歌甚至比主歌还稀（0.72–0.90）。这与用户听到的"从头到尾一个节奏"完全一致。

### 1.3 根因与"提示词无效"的既有证据

- 2026-10-15 的 A/B 已经证明：**改写 caption/tag 的措辞控制不了整体动态**
  （把动态写在前三句、缩短 500 字符的"硬"tag 反而更平：躯干 -1.7 dB vs -3.3 dB）。
  所以"再写一版更强调副歌密集的 tag"这条路**不需要再试**。
- 但 **计划是符号化的**：`d2d2d2ef-|` 里每个音符的时值、音高都写死了。
  而且已验证**改计划能改变渲染结果**：2026-10-15 把 intro 从 20 小节裁到 2 小节，
  渲染后人声首句从 30.0s 提前到 3.1s。计划编辑 → 音频变化，通路是通的。

**因此：节奏密度与音区只能从计划层确定性地下手，不能靠提示词。**

### 1.4 交叉验证：计划指标 = 听得到的指标

对 `01_hammer_and_hymn`（计划总长 183.4s，实际渲染 184.6s，误差 1.2s/3min）用
faster-whisper 词级时间戳按"计划推导出的段落边界"逐段统计：

| 段落 | 计划 起音/秒 | 实测 词/秒 | 比 |
|---|---|---|---|
| verse | 1.47 | 1.27 | 0.86 |
| chorus | 1.44 | 1.16 | 0.81 |
| verse | 1.64 | 1.53 | 0.93 |
| chorus | 1.36 | 1.13 | 0.83 |
| bridge | 1.20 | 0.89 | 0.74 |
| chorus | 1.39 | 1.23 | 0.88 |
| interlude | 0.16 | 0.18 | 1.13 |

**两列逐段同步**：所有**演唱段**的换算比（词/秒 ÷ 起音/秒）都在 **0.74–0.93**（约 0.84），
即一个词常被拖过多个音符。末段 interlude 是唯一例外（比 >1）：那里模型补唱了计划没记的句子——
说明计划不覆盖 100% 的实际演唱，但**段与段之间的相对形状是准确的**，这正是要用的部分。
=> 计划层指标可以作为听觉密度的**廉价、确定性代理**，不需要每次渲染+转写。
=> 同一张表也说明：这首的副歌（1.16）**比主歌（1.27）还稀**，chorus/verse = **0.84**。

同曲 20 秒窗密度曲线（`word_rate.py`），几乎是一条直线 —— 这就是"全程一个节奏"的数值形态：

```
  0.0s 1.20 w/s   40.0s 1.20 w/s   80.0s 1.15 w/s  120.0s 1.35 w/s  160.0s 0.16 w/s
 20.0s 1.20 w/s   60.0s 1.40 w/s  100.0s 0.95 w/s  140.0s 0.45 w/s
```

参考曲要做的就是把这条线变成**有形状的曲线**（低频段低、高潮段明显抬高）。

### 1.5 修法 A：计划级重写（**已实现**：`plan_shape.py`）

工具：`tools/generation/plan_shape.py`（16 个测试，`tests/test_plan_shape.py`）。
只改 `V: Vocal` 声部，两个算子：

```bash
P=vendor/ACE-Step-1.5/.venv/Scripts/python.exe
$P -I tools/generation/plan_shape.py --file <score.abc> \
    --reduce verse:2 --split chorus:2 --out shaped.abc --report
```

1. **`--reduce SECTION:FACTOR`（主歌降密度）**：每 FACTOR 个起音保留一个，被丢掉的音
   **把时值交给前一个音**（于是变成拖长，而不是静音），并可在休止上"跨过去"延长。
   小节内第一个起音永远保留 → 每小节仍然踩在拍上。
   例：`"D#m"d4a4` → `"D#m"d8`；`"C#"g4z3d` → `"C#"g5z3`（总时长 8 单位不变）。
2. **`--split SECTION:MAX_UNITS`（副歌升密度）**：超过 MAX_UNITS 的音符**拆成同音重复**，
   于是长音变成"字字砸在拍上"。跨小节连音（`d8-|d8`）也会被拆开并解除连音——
   同样的小节总时值，起音数从 1 变 8。
   例：`"D#m"a4z2dd` → `"D#m"a2a2z2dd`；`"D#m"d8|"D#m"d8` → 8 个 `d2`。
3. **`--hook SECTION`（副歌钩子回归，2026-10-16 新增）**：把**第一段 SECTION 的旋律
   （连和弦记号一起）原样复制**到后面各段；小节数不同时按动机循环铺满，并按**整八度**
   对齐目标段的音区（八度不改变调式，不会与和声打架）。歌词是另行喂入的，所以
   "末副歌歌词必须全新"不受影响。依据见 §1.6.2（我们 0.902 vs 参考曲中位 0.978）。
4. **`--thin SECTION:FACTOR`（温和降密度）**：丢掉的音**变等长休止**（而不是拖长），
   音节长度不变、呼吸变多。`--reduce` 的温和替代品（`--reduce` 已因丢歌词被否决）。
5. **改音区**：仍用 `yue2_plan_edit.py --section ... --semitones ...`（已验证能正确重写
   `K:` 调号下的临时记号）。主歌下移、副歌保持/上移；末副歌升全音见 `--final-lift 2`。

**实测（2026-10-16，全仓库 59 个真实计划全量扫描）**：
- 守卫**零触发**：小节数、每段秒数、和弦记号全部逐字节保持（每个小节的总时值在改写时当场校验，
  对不上就报错拒写）。
- 主歌密度 **59/59 下降**，副歌密度 **59/59 上升**；
  平均 副歌/主歌 比值 **1.06 → 4.76**（`reduce 2` + `split 2` 偏激进，可调）。
- 单曲例（01_hammer_and_hymn）：主歌 1.55 → 0.94，副歌 1.40 → 2.32，**比值 0.90 → 2.47**。

**已知副作用（必须知道，别当成 bug）**：
- 降密度会**丢掉被删音符的音高**，音域可能因此收窄 1–2 个半音（实测 lo 68→70）。
  音高集合只会是原来的子集，不会新增，音区也不会漂到别的音域。
  需要音区更低就走算子 3（移调）。
- 密度是"字多字少"的量，**不改变旋律轮廓的方向**；要改旋律形状需要新算子（未做）。

**调参方法**：`--report` 会打印改写前后每段的密度/音区表，按比值逐步调 FACTOR 与 MAX_UNITS，
直到比值落进 §1.6 标定出的目标区间（临时目标 1.8）。

**历史坑（写代码时踩过，值得记住）**：
- 和弦记号 `"D#m"` 里的 `D` 会被音符正则当成音符 → 被吃掉并吞掉紧随其后的真音符
  （输出 `"D5#m"`）。记号必须先于音符匹配、按原样保留。
- 跨小节连音 `d8-|d8-|d8` 是**一个**长音，不是 3 个起音；把它算密会正好抵消掉副歌的判断。
- 无 `V: Vocal` 的纯器乐段必须保留自身小节长度，否则后续所有段落边界错位（`word_rate.py` 依赖它）。

### 1.6 修法 B：参考曲对齐工作流（"先模仿"的落地）

要模仿就得先**量出参照物**。计划建一个 `tools/generation/ref_profile.py`：

输入：参考曲音频（**需要用户提供本地文件**，见 §5 待确认项）。
处理：Demucs 分离人声 → 人声干声上做
1. **吐词速率曲线**：librosa onset strength 在语音频段做起音检测，按 5–10 秒窗口统计，得全曲密度曲线；
2. **音区曲线**：pyin 提取 F0，取每窗中位数与 5/95 分位，得音区随时间的走向；
3. **段落划分**：mel 谱自相似/新颖度做结构分割（或人工标注），得到 verse/chorus 边界；
4. **输出**：`refs/<name>_profile.json` —— 每段的吐词速率、音区中心/跨度、静音占比，
   以及全曲的"主歌→副歌 密度比""音区抬升半音数"。

拿到 2–3 首参考曲的剖面后，**§1.5 的目标数字就不再是我拍的，而是实测的**。
这也是本项目一贯的做法（`arc_qa.py` 用测量代替形容词）。成本很低：Demucs 1–2 分钟/首（GPU）+ 分析秒级。

#### 1.6.1 首批实测（2026-10-16，12 首参考曲已下载到 `human_refs/refs/`）

工具已落地：`tools/generation/ref_profile.py`（人声分离 → 每 10 秒窗口的响度/起音速率/音区），
`--whisper` 时再叠一层吐词速率（复用 `word_rate.py` + `tools/asr/.venv`）。
**注意两个口径的可靠性差异**（下同）：

- **起音/秒**：人脸分离轨上的瞬态检测。战斗曲的 demucs 人声轨仍带鼓的串扰，
  实测 **2.8–3.4 个起音才对应 1 个词**（本曲 3.43、Wildfire 2.76），所以它**只能当快速筛选**，
  不能拿来做目标数字。
- **词/秒**（whisper）：较可信，也是我们这边 `plan_metrics` 交叉验证过的口径。

**同口径对照（whisper 词密度，10 秒窗，都走 demucs 人声轨）**：

| 曲目 | floor（p25） | peak（p90） | 窗内摆幅 | loud/soft 均值比 | 音区抬升 |
|---|---|---|---|---|---|
| Wildfire | 0.90 词/秒 | 1.60 | ×1.78 | **×1.20** | +1.6 半音 |
| 我们的 01_hammer_and_hymn | 0.72 | 1.63 | ×2.26 | **×0.92** | +4.7 半音 |

**结论（10 首人声参考曲的合计 vs 我们）**：

| 指标 | 参考曲中位（四分位） | 我们的 01 | 判定 |
|---|---|---|---|
| 吐词密度摆幅 | **×1.98**（1.82–2.59） | ×2.05 | 一致 |
| 密度底 floor | 0.88（0.80–1.30）词/秒 | 0.80 | 略低但在四分位内 |
| 密度峰 peak | 1.95（1.69–2.22）词/秒 | 1.64 | 略低 |
| 响处/静处（band x） | ×0.89（0.76–0.97） | ×0.92 | 一致 |
| 音区抬升 | +2.2 半音（0.6–4.5） | +4.7 | 我们更高 |

**=> 在吐词密度的所有维度上，我们与顶级参考曲没有显著差异。**

> ⚠️ **记录一次被推翻的中间结论**：只拿 Wildfire 一首比时，它"响处更密（×1.20）"而我们
> "响处更稀（×0.92）"，我据此写过"我们方向是反的"。**扩充到 10 首参考曲后，×0.89 才是这个
> 流派的中位**——单曲样本是噪声，我们的 ×0.92 完全正常。教训：**参考系必须用一组，
> 不能用一首**（这也是 §1.6 一开始就要求 2–4 首的原因）。

**所以"从头到尾一个节奏"这个听感，用吐词密度统计复现不出来。** 差异藏在别的维度。

#### 1.6.2 钩子相似度——**找到了**（2026-10-16）

新增指标 `hook_similarity`（`ref_profile.py`）：取该曲**最响的 25% 窗口**，
两两算 chroma 余弦相似度取均值。含义是"**响的段落之间听起来像不像同一段**"——
真实副歌是同一个钩子反复回来（高），通谱体每次换一段（低）。同一把尺子，13 轨全量：

| 组 | hook 相似度 |
|---|---|
| 10 首人声参考曲 | **中位 0.978**（四分位 0.947–0.982）；最低 Ruelle 0.946、Within Temptation 0.908 |
| **我们的 01_hammer_and_hymn** | **0.902**（演唱窗占比 94%，不是器乐造成的假象） |

**我们的"副歌"彼此相似度低于任何一首人声参考曲**（只有 Within Temptation 与我们接近）。
听感翻译：真实副歌是"同一个钩子又来了"，我们的是"**和弦一样，但每次旋律都换个说法**"——
所以听不出副歌感，只觉得"从头到尾一个节奏 / 音调变化不大"。
这与用户原话完全吻合，且**是整个批量的系统性特征**（我们的计划里三段副歌和声完全相同、
旋律各写各的）。

**可控性**：这是**计划层可确定修复**的——把第一段副歌的旋律**原样复制**到后面的副歌
（小节数不同就按动机循环/截断），歌词仍由 lyric 文件单独喂入，所以
"末副歌歌词必须全新"（用户 2026-10-15 的要求）不受影响，而**旋律钩子回来了**。
这正是真实歌曲的做法。

**下一步**：实现 `--repeat-hook chorus`（计划变换器，与 `trim_intro`/`transpose_section` 同类），
离线 `plan_metrics` + `hook_similarity` 验收，再单曲渲染确认。

**已实现并全量验收（`--hook SECTION`，2026-10-16）**：60 个真实计划跑 `hook chorus`，
**时值零改动**（每段小节数与秒数逐字节核对），三段副歌的旋律（连同和弦记号）变成同一句；
音域外扩最大 5 半音（仅 2 段 >4），加整八度对齐后不再出现"末副歌被降八度"的极端情形。
与密度算子的组合效果（同批 23 个 take 的副歌/主歌 起音密度比，中位）：

| 配置 | 副歌/主歌 密度比 |
|---|---|
| 原始 | 1.13 |
| `split chorus:2` | 2.60 |
| **`hook chorus` + `split chorus:2`** | **2.51** |
| 仅 `hook chorus` | 1.46 |

=> **钩子几乎不花密度代价**，两个修复可以同时上。故 2026-10-16 的整天批次用
`--shape 'hook chorus' --shape 'split chorus:2'`。

| E6 | **参考曲的段落级剖面**（而不是全曲平均）：由用户指出具体时间点后量那几段 | 依赖用户 | 校准"冲击感"到底来自密度还是编曲（§1.6.1 的矛盾） |

**渲染成本基准**（12GB 卡，YuE2）：658–1889 秒/首，典型 ~800 秒；同 brief 方差可达 2 倍。
后几个实验可以合并到一次批量里跑，避免反复加载模型。

#### 1.7.1 E1 结果（2026-10-16，`reduce verse:2` + `split chorus:2`）

同 brief、同 seed（1200），只改计划；渲染 761 秒；渲染留存的 `score.abc` 与改过的计划**逐字节相同**
（说明渲染器确实按计划唱）。用 `word_rate.py` 按计划边界逐段量：

| 段 | 原版 词/秒 | 改后 词/秒 | 改后 计划起音/秒 |
|---|---|---|---|
| verse 1 | 1.27 | **0.00（25 秒内 whisper 检不出任何词）** | 0.83 |
| verse 2 | 1.53 | 0.84 | 1.06 |
| chorus ×3 | 1.16 / 1.13 / 1.23 | 0.99 / **2.08** / **1.84** | 2.11 / 2.62 / 2.22 |
| bridge | 0.89 | 0.82 | 1.20 |
| **副歌/主歌** | **0.84** | **1.95**（剔除被清空的主歌 1） | — |

**结论**：
1. **机制成立且方向正确**：副歌实测吐词密度 ×1.4–1.8（1.16 → 1.64 均值），比值 0.84 → 1.95，
   落进目标区间；桥段与间奏未受影响（说明算子只作用在目标段落）。
2. **`reduce 2` 对主歌过头**：第一段主歌 25 秒变成整段拖长音，**歌词等于丢了**（0 词检出）。
   对一首以歌词为卖点的战斗曲这是不可接受的。
3. **顺带暴露一个门控缺陷**：首句落点从 3.1s 变成 **19.16s**——不是前奏变长，而是
   "第一个可辨词"被推后了。**首句门控会被"长拖音开场"误判**，需要与密度指标联动。
4. 参数下一步：主歌改用更温和的算子（只并"过短音符"，保留旋律骨架），或 `reduce 2` 只作用于
   非首段主歌；副歌 `split 2` 保留。**最终参数仍等 §1.6 的段落级标定**（§1.6.1 的矛盾未解）。

## 2. 问题二：高音处的机械杂音

### 2.1 现象（用户原话）

> "高音会有杂音……集中在部分的高潮部分。这种杂音不像是人类歌手的破音，反而是一种
> 带有缺陷的机械音。当然不是所有歌曲都有。"

三个关键词决定了技术路线：**只在高音/高潮**、**不是破音**（不是振幅/削波类失真，是音色类失真）、
**不是每首都有**（存在"生成运气"成分 → 门控重摇是可行的兜底）。

**现有客观工具对它是盲的（2026-10-16 实测）**：把 9 首已交付曲跑一遍现有全部客观指标
（`tools/generation/audio_qa.py --degeneracy`）：

| 指标 | 9 首的读数 | 结论 |
|---|---|---|
| `harsh`（旧机器噪声代理：zcr 异常帧） | **全部 0 / h.ratio 0.0000** | 为 ACE-Step/HeartMuLa 标定的检测器在 YuE2 上**完全失效** |
| `dips`（≥150ms 断裂） | 2–13，全部通过 | 无信息量 |
| `clicks`/s | 0.6–71.7（04 是 0.6，01 是 71.7） | **被打击乐瞬态污染**：相差 100 倍的"爆音"不可能全是缺陷（用户只说"部分高潮"），战斗中鼓/太鼓本身就是采样级跳变 |
| 结尾退化门控 | 9 首全 `ok` | 不触发 |

**即：我们手上现有的所有客观指标，没有一项能看见你听到的那个机械音。**
这不是"阈值没调好"，而是这些指标当初是为**别的后端、别的问题**标定的。
所以 §2.4 的听音标定不是可选项，是唯一的入口。

### 2.2 已有结论（不要再重复踩坑）

- 旧的 ACE-Step/HeartMuLa 时代，这类杂音的根因是**编码器帧率**：HeartCodec 硬性 12.5 Hz
  （80 ms/帧），快变瞬态被抹平；`happy-new-year` 只换了 LM，HeartCodec 只"优化解码质量"，
  **无法靠调参消除**——这是当初换到 YuE2 的原因。
- YuE2 是 48 kHz / 25 fps latent，帧率问题缓解，但**换后端不等于消灭了这类音色缺陷**，
  只是换了机制。所以 YuE2 上的高音杂音需要**重新标定**，不能照搬旧检测器。
- 旧检测器（zcr 0.38–0.79 + 4–10 kHz 突发）是为 HeartMuLa 标定的；且在旧后端上
  它**分不清齿音和机器噪声**（真人参考也触发 14–149 个事件）。**不要直接搬到 YuE2 上当地面真值。**
- 旧后处理链（frame repair / humanize / WORLD 重合成）已被证明有硬天花板，
  2026-08-15 起原则是**源头干净、零修补**。任何修复方案都必须保留源文件、只做 A/B、不自动晋升。

### 2.3 四个假设与各自的测法

优先级从高到低。每条都必须能在**同一首歌内部**做对照（高音帧 vs 低音帧），
以排除"歌与歌之间本身就不一样"的干扰。

| # | 假设 | 测法（在分离出的人声干声上） | 判据 |
|---|---|---|---|
| H1 | **高 F0 的谐波重建失败**：F0 升高时谐波变稀，声码器/解码器在 8–16 kHz 重建出非谐波成分 | 按帧分箱（F0 = 200–300 / 300–400 / >400 Hz），比较各箱的"谐波内/谐波间能量比"与 8–16k 相对中频的过量 | 高 F0 箱的谐波间能量或 HF 过量显著高于低 F0 箱 |
| H2 | **长音高音漂移**：计划里长时值的高音（`d8-` 连音）给模型更多帧去漂，听成"机械"（稳定但无颤音、相位锁死） | 直接从**计划**取出"时长 ≥ 全音符 且 音高 ≥ 段落 90 分位"的位置，对准音频逐帧看：HNR、颤音深度（F0 4–7 Hz 调制幅度）、谱平坦度 | 缺陷时间戳与这些位置显著重合；且这些帧颤音深度≈0 |
| H3 | **高潮限幅/削波**：混音在最高潮推满，人声被限幅器压成方波 | 逐帧 crest factor 与峰值统计；找平顶波形 | 缺陷段 crest 显著塌陷 + 出现平顶 |
| H4 | **纯生成运气（seed 相关）**：NAR 阶段偶发失败 | 同 brief、同计划、换 seed 各渲染一次（可只渲染出问题的那一段做成短计划，成本 ~3 min/次） | 缺陷跟着 seed 走 = H4 成立；跟着音符走 = H1/H2 |

**H2 是本项目独有的优势**：计划里有精确的音符时值与时高，可以**在渲染前预测**
哪些位置最可能出问题，不必听完再猜。

### 2.4 听音标定流程（我无法替代的环节）

我听不到音频。所以缺陷检测器必须**用你的耳朵标定**：

1. 你听 9 首已交付曲（`outputs/2026-10-15_epic_en/selected/`），记下听到机械音的**时间戳**
   （精确到秒即可，例如 `03_the_gate_holds 1:12–1:18`）。
2. 我把这些时间戳对应的帧抽出来，与全曲其他帧对比，找**能分开这两组的统计量**。
3. 用该统计量给全部曲目打分 → 得到"嫌疑清单"，你只需复核被标记的片段（而不是重听全曲）。
4. 阈值写进门控 → 之后自动重摇，不需要你每次听。

这个循环我们已经跑过两次（`arc_qa` 的动态、`diction_qa` 的吐字），是有效的方法。

### 2.5 处置阶梯（按"改动从小到大"）

1. **门控重摇**（首选，符合"不是每首都有"）——检测器命中 → 换 seed 重渲染。
   等价于已有的长度门控/首句门控/结尾退化门控。
2. **计划级回避**（零音频处理）——长高音拆成两段（加呼吸）、高音段落整体下移 1–2 半音、
   减少同音长音密度。由 §1.5 的同一套变换器提供。副作用是听感变化，需要 A/B。
3. **vocal-only 外科降 HF**（`tools/vocal_repair/surgical_vocal_variant.py` 已存在）——
   只处理分离后的人声、伴奏不动、**源文件永远保留**、不自动晋升。仅作 A/B 备选。
4. **换后端**——不在本期计划内（YuE2 是目前最优）。
